# mouseshop — контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Учебный магазин компьютерных мышей на основе проекта КР №1. Пять страниц, шесть моделей, характеристики и демонстрационная форма заявки. Используются HTML, CSS и небольшой файл обычного JavaScript. Bootstrap и другие фреймворки не подключены.

Автор: Рупаков Павел Анатольевич, группа ЭФБО-03-25.

Репозиторий: https://github.com/rupakpav/kr3-responsive-shop

## Запуск

Откройте `index.html` в браузере или запустите папку через Live Server в VS Code. Установка зависимостей для сайта не требуется. Фотографии, CSS и JavaScript хранятся в проекте.

## Практическое занятие №12

- `css/responsive.css` подключён после `css/style.css` на всех пяти страницах. На каждой странице есть `viewport`.
- Базовая раскладка рассчитана на телефон. Расширение выполняется медиазапросами `min-width`.
- Меню на телефоне располагается в колонку, с 768 px — в строку с переносом. Шапка не перекрывает содержимое.
- Hero-блок одноколоночный, с 900 px — двухколоночный. Размер заголовка меняется через `clamp()`.
- Сетка карточек: одна колонка на телефоне, две с 640 px, три с 1024 px. В каталоге с боковым фильтром две колонки сохраняются до 1280 px, затем используются три.
- Фильтр находится перед товарами на маленьком экране. С 1024 px занимает боковую колонку и использует `position: sticky`.
- Изображения ограничены `max-width: 100%`. Для товаров заданы `srcset`, `sizes`, размеры и `loading="lazy"`. В hero используется `picture` с WebP и запасным JPEG; изображение первого экрана загружается без задержки.
- Форма одноколоночная на телефоне, с 768 px часть полей занимает две колонки. Поля и кнопки имеют высоту не менее 44 px. Форма в диалоге остаётся одноколоночной.
- Таблицы помещены в `.table-wrapper` с горизонтальной прокруткой. Прокручивается таблица, а не вся страница.
- Диалог ограничен шириной и высотой экрана, длинное содержимое прокручивается.
- Кнопка «Наверх» закреплена только с 1440 px, в свободном поле справа. На меньшей ширине она находится внутри подвала в обычном потоке.

## Практическое занятие №13

Проверена семантика: один `h1` на странице, последовательные заголовки, `header`, `nav`, `main`, `footer`, осмысленные ссылки и настоящие кнопки. Текущая страница отмечена `aria-current="page"`.

Исправления доступности:

- Добавлена ссылка «Перейти к основному содержимому». Она появляется при первом нажатии Tab и переводит фокус в `main`.
- Для всех интерактивных элементов задан заметный `:focus-visible`.
- Светлая тема использует тёмный текст и зелёные акценты. У основных кнопок исправлен недостаточный контраст белого текста с прежним светло-розовым фоном.
- Фотографии имеют осмысленные `alt`.
- Поля связаны с `label`; обязательность указана текстом. Ошибки выводятся рядом с полями и связаны через `aria-describedby`. `aria-invalid` добавляется только при ошибке.
- Диалог имеет заголовок через `aria-labelledby`, открывается с клавиатуры, закрывается кнопкой и Escape. При закрытии фокус возвращается на кнопку открытия.
- Таблицы имеют `caption`, заголовки `th` и `scope`. Контейнер таблицы доступен с клавиатуры и прокручивается стрелками.
- По замечанию Lighthouse удалён лишний `aria-label` у «Наверх»: доступное имя теперь совпадает с видимым текстом.
- При `prefers-reduced-motion: reduce` отключается плавная прокрутка.

## Проверка адаптивности и поведения

Проверка выполнена в Firefox через DevTools. На каждой из пяти страниц проверены все указанные ширины:

| Ширина | Режим | Результат |
| --- | --- | --- |
| 360 px | Телефон | Общего горизонтального скролла нет |
| 430 px | Большой телефон | Общего горизонтального скролла нет |
| 768 px | Планшет | Общего горизонтального скролла нет |
| 1024 px | Небольшой desktop | Общего горизонтального скролла нет |
| 1440 px | Широкий desktop | Общего горизонтального скролла нет |

Проверены загрузка изображений, локальные ссылки и якоря, отсутствие повторяющихся `id`, связи ARIA и подписи полей. Ошибок JavaScript в проверенных сценариях нет. Проверены открытие и закрытие диалога, возврат фокуса, передача выбранного товара в заявку, пустые обязательные поля, неправильный e-mail, корректное заполнение формы и прокрутка таблицы клавиатурой.

Выбор изображения проверяется по `currentSrc`: браузер использует варианты из `srcset`, в hero выбирает WebP. Проверку можно повторить во вкладке Network с фильтром Img и отключённым кешем.

| Страница | Accessibility | Отчёт |
| --- | --- | --- |
| Главная | 100 / 100 | [index-accessibility.html](lighthouse/index-accessibility.html) |
| Каталог | 100 / 100 | [catalog-accessibility.html](lighthouse/catalog-accessibility.html) |
| Заявка | 100 / 100 | [order-accessibility.html](lighthouse/order-accessibility.html) |

Отчёты получены на локальном сервере. Время запуска, версия браузера и подробные результаты сохранены внутри HTML-отчётов. Автоматическая оценка дополнена проверкой клавиатуры и визуальным просмотром; она не заменяет проверку с экранным диктором.
